# 正式实施计划（2026-10-18 定稿）

目标不变：**人不在桌前、但在同一个 Wi-Fi 下，也能看到 Hermes 在干什么、并对它的 clarify / approval 按键作答。**
不做 WAN 远控（那是 Happy / 首尔服务器的事）。

## 一、要买什么

| 项 | 型号/规格 | 用途 | 备注 |
|---|---|---|---|
| 主机 | **M5Stack Cardputer-Adv**（ESP32-S3FN8，8MB Flash，无 PSRAM，240×135 单色屏 + 键盘 + 麦克风 + 侧键 BtnA） | 遥控器本体 | 必须是 **Adv**：老款 Cardputer 的键盘/TCA8418 与麦克风接法不同，固件的 `M5Cardputer.Keyboard.keysState()` 只对 Adv 成立 |
| 线材 | USB-C **数据线**（不是只有电的充电线） | 烧录 + 串口配网 | 认不出串口时先换线，再换端口 |
| 网络 | 家里的 **2.4G** Wi-Fi，与 Mac 同网段 | 板子连桥 | 5G-only SSID、访客隔离、AP 隔离都会失败 |

不需要：SD 卡、蓝牙、额外电源（板子内置电池）。可选：一个桌面支架（板子立在桌上比平放好用）。

## 二、施工顺序（每一步都有明确“过没过”）

### 第 1 步：Mac 侧先跑通（不需要硬件）

```bash
cd ~/Documents/hermes-remote
python3 -m venv .venv && .venv/bin/pip install -e .     # 或直接用 Hermes 自带的 python
.venv/bin/python -m unittest discover -s tests           # 期望：63 passed
.venv/bin/python -m hermes_remote.cli discover --print   # 期望：找到桌面后端 + 端口
.venv/bin/python -m hermes_remote.cli doctor
```

过关标准：测试全绿；`discover` 能报出 `pid=… → 127.0.0.1:PORT`。
不过关就别往下走——桥都没通，烧固件没有意义。

### 第 2 步：真后端 + 真屏帧（仍然不需要硬件）

```bash
.venv/bin/python -m hermes_remote.cli run --rediscover --no-beacon
# 另开一个终端，用模拟设备抓一帧（仓库里的 devsim 或 README §7 的小脚本）
```

过关标准：日志出现 `attached session <短id> status=…`，设备侧收到屏帧并能解出 4050 字节位图。
**这是本机唯一一次“真后端验证”**，2026-10-18 已经过了一次（见 `docs/live-check-2026-10-18.png`）。

### 第 3 步：板子到手，先编译再烧

```bash
brew install platformio        # 或 pipx install platformio
cd ~/Documents/hermes-remote/firmware
pio run                        # 第一次一定会报库/板级问题，按 firmware/README.md 的清单改
pio run -t upload              # 按住 G0 再插线进下载模式
pio device monitor             # 115200，看启动日志
```

过关标准：编译通过 + 串口看到 `READY hermes-remote-provision`。

### 第 4 步：配网

```bash
.venv/bin/python -m hermes_remote.cli provision --port /dev/cu.usbmodemXXXX --ssid '家里2.4G'
# 密码交互式输入；也可以 --password-stdin
```

**建议同时写死桥的地址**（`--bridge-host <Mac 的局域网 IP> --lan-port 47823`）：
钉死之后板子不再听广播，同网段的假广播骗不走它（代价：Mac 换 IP 要重新配网，所以先给 Mac 做 DHCP 保留）。

过关标准：板子重启后屏上出现 Hermes 会话标题，而不是 `NO BRIDGE` / `RECONNECTING`。

### 第 5 步：真机六处确认（firmware/README.md 的清单）

1. 屏幕方向对不对（`setRotation(1)`）；
2. 键盘：`1-4`、`enter`、反引号当 ESC；
3. **侧键 BtnA**：按住能进录音、松开进预览（这一处已改过判定顺序，但仍要在真机上确认 BtnA 就是侧键）；
4. 麦克风：`M5.Mic.begin()/record()` 返回值；
5. **首条 auth 消息**：连上后屏上直接出会话（而不是 `RECONNECTING`），串口日志里没有 401/4401；
6. **翻页键**：审批页按 `fn` / `back` 能翻页，翻完前按 1 提示“还有 N 页没看”。

不过关只影响对应那一块：屏和按键不行就是不能用；麦克风不行只是不能说话作答。

### 第 6 步：端到端验收（用真人动作，不看日志）

| # | 动作 | 过关标准 |
|---|---|---|
| 1 | 让 Hermes 跑一件要连续审批三次的活，人走开 | 屏上 1 秒内出现“等你决定”，按 3 次 1，活干完，全程没碰 Mac |
| 2 | 在 Mac 上先答同一个问题 | 板子的卡片 1 秒内消失；审计里没有第二次作答 |
| 3 | 拔掉 2.4G 十秒再插回 | 屏上 `RECONNECTING` → 恢复后画面与状态一致 |
| 4 | 断网期间乱按 1/2 | 恢复后没有“补发”的作答（审计里无对应记录） |
| 5 | 按住侧键说一句话 | 先出预览，`enter` 才发；`esc` 放弃 |
| 6 | 重启桌面 App | 桥自己重新发现端口并挂上（`--rediscover`） |
| 7 | 发一条 `python3 -c '...'` 审批 | 屏上标“危险操作”，**按一次不上膛、按两次才发** |
| 8 | 发一条 60–100 字符的长命令 | 屏上显示“第 1/N 页”，不翻完按 1 不放行；翻完再按两次 1 |
| 9 | 发一条没有 `command` 的审批（或 command 为空） | 屏上写“不能在设备上批”，按 1 无效，按 2 拒绝成功 |

9 条全过 = 可以日常用。

## 三、日常怎么跑

- 桥**前台**跑在终端里（`run --rediscover`），不装 launchd（原因见 README §6 第 1 条）；
- Mac 要开盖 + 接电；合盖就睡，任务本身也停；
- 换 Wi-Fi / 换网段 → 重新 `provision`（密码交互式输入，不进 shell history）；
- **丢板子或者怀疑 token 泄漏** → `hermes_remote.cli rotate-token`：旧 token 立即失效，
  用新 token 重新 `provision` 一次；
- 每次验收完把结果补进 `docs/验证记录.md`（模拟 / 真后端 / 固件编译 / 硬件 四层分开写）。

## 四、出问题先看哪里

| 现象 | 先查 |
|---|---|
| 屏上 `桥连不上 Hermes 后端` | `discover --print`；桌面 App 是否在运行；`--rediscover` 是否加上 |
| `还没有会话` 一直不变 | 桌面 App 里当前有没有活着的会话（`session.active_list` 为空就是没有） |
| 板子一直 `NO BRIDGE` | 2.4G？同网段？AP 隔离？配网写过 `HOST` 但 Mac 换了 IP？ |
| 按了 1 没反应 | 审计里看有没有 `request.delivery_failed` / `request.expired`；过期请求是故意的 |
| 屏花 / 画面错位 | 先看 `screens/preview.png` 是否正常；正常就是固件画屏/方向问题，不正常是渲染问题 |

## 五、明确不做（第一版范围）

- WAN 远控 / 手机当屏（走 Happy 或 Tailscale，不在这块板子上做）；
- 多会话看板、历史回放；
- 语音说完即发（识别错字代价太大，坚持预览→确认）;
- TLS + 设备证书（威胁模型是“信任家里的 2.4G”）。
